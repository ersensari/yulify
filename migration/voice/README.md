# Yulify voice migration helpers

These helpers are isolated prototypes, with no package manifest, registration, runtime connection, database mutation, network request or deployment. They are not a complete voice provider.

`room-auth.mjs`: `hasRoomBearer(room, sessionId, authorization)` checks an existing room's session binding and its bearer credential using `timingSafeEqual`, preserving the current bridge's scheme and case semantics. A nonempty room token and explicit `room.sessionId` equality are required. Production replacement would be inside `authorizedRoom` in Yulify `server/src/api/minicpm-duplex.ts`: first call `pruneExpiredRooms()`, look up `active.get(sessionId)`, then call this helper; only on success update `lastSeenAt` and return that room. Do not move these endpoints behind cookie-only extension routes or change existing service authentication. This helper does not create tokens, check TTL, authenticate the portal service or own the active map. The live bridge currently mounts before cookie auth and uses a per-room secret; other portal routes use their own auth.

`pcm24.mjs`: `pcmTo24k(24000 | 48000)` exposes `push(Uint8Array)` and `finish()`, returning byte buffers. Supply one fresh converter per stream. Input and output are mono signed 16-bit little-endian raw PCM, with the caller validating actual media type, channel count and sample rate before selecting it. 24 kHz passes through exactly. 48 kHz uses a stateful, windowed-sinc 63-tap low-pass FIR and 2:1 decimation, with zero padding and a 31-input-sample lookahead. Output has ceil(input samples / 2) samples and no chunk boundary artifacts. Odd-byte boundaries are supported; an incomplete final sample is rejected. Each push allocates output proportional to that input chunk; caller owns bounded streaming, cancellation and upstream cleanup. This implementation neither parses nor resamples WAV, Ogg or other rates, nor does it change the LiveKit worker audio path. The v0.2 `VoiceProvider.speak` contract accepts 24 kHz PCM or WAV; only enable conversion after extracting the real Yulify synthesis service and verifying actual format/rate headers. The 24->48 conversion is intentionally absent: this API only consumes 24 kHz and no identified integration requires upsampling.

Run `node --test migration/voice/helpers.test.mjs` from the repository root. Checks cover authentication mismatch/session binding, byte-for-byte passthrough, odd byte chunking, chunk-invariant decimation and output length, 2 kHz passband, 18 kHz alias suppression, invalid rates and truncated PCM. These are component checks with generated signals, not acoustic or full voice validation. Streaming resampling changes the output's sample rate and must be combined with updating response headers, downstream cancellation/backpressure, and tests of actual engine responses in a future integration.
